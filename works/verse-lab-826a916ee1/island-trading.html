01やさしい

島内取引ってなに?

UEFNには、自分のアイランドの中でV-Bucksと引き換えにアイテムを販売できる「In-Island Transactions(島内取引)」 という仕組みがあります。2025年12月から、開発者は自分のアイランドから直接アイテムを販売できるようになりました。

たとえ話でわかる 島内取引

文化祭の模擬店を思い浮かべてください。お店に並んだ商品には、値札(Price)と引換券(entitlement)があります。
Durable(耐久型)の商品は、一度買った鉛筆のようにずっと使い続けられるもの。
Consumable(消費型)の商品は、かき氷の食券のように使ったらなくなるものです。

🆕
できたばかりの新機能です

島内取引は2025年に登場したばかりの新しい仕組みで、細かいクラス名やイベントの受け渡し方は今後のUEFNアップデートで調整される可能性があります。骨組みの考え方を押さえたうえで、実際に書くときはUEFNのプロジェクトブラウザにある「In-Island Transactions Feature Example」というお手本プロジェクトも一緒に確認すると確実です。

Durable(耐久型)Consumable(消費型)
たとえ一度買った鉛筆かき氷の食券
使ったらずっと持ち続けられる個数が減っていく
購入回数基本1回のみ(MaxCountは自動で1)MaxCountまで複数回購入可能
02やさしい

商品(entitlement)を定義する

お店に並べる商品は、entitlementという型の仲間として定義します。「これは何という商品で、耐久型か消費型か」を1つのクラスで表します。

verse
using { /Fortnite.com/IslandTransactions }

# 「耐久型」の商品券: 一度買えば、ずっと持っておける
golden_pickaxe_entitlement := class(entitlement):
    Consumable : logic = false   # false = Durable(耐久型)

# 「消費型」の商品券: 使うとインベントリから消える
healing_potion_entitlement := class(entitlement):
    Consumable : logic = true    # true = Consumable(消費型)
    MaxCount : int = 5           # 一度に最大5個まで所持できる
📦
class(entitlement)ってどういう意味?

golden_pickaxe_entitlement := class(entitlement):は、「golden_pickaxe_entitlementという新しい商品券を、entitlementという商品券の仲間として作る」という意味です。動物図鑑にたとえるなら、「entitlement」という大きなカテゴリの中に「黄金のツルハシ」という具体的な商品を1つ追加しているイメージです。

📝 演習問題 01

「speed_boost_entitlement」という名前で、消費型(Consumable = true)、最大所持数3個(MaxCount = 3)の スピードブーストの商品券を定義してみましょう。

verse
speed_boost_entitlement := class(entitlement):
    Consumable : logic = true
    MaxCount : int = 3
03やさしい

値札(offer)をつくる

商品券を定義しただけでは、まだ値段がついていません。値札にあたるentitlement_offerを作って、 名前・説明・値段(V-Bucks)を決めましょう。

verse
golden_pickaxe_offer<public> := class(entitlement_offer):
    Name : string = "黄金のツルハシ"
    ShortDescription : string = "キラキラ光る特別なツルハシ"
    Description : string = "収穫の音がゴージャスになる、見た目だけの特別アイテムです。"
    EntitlementType : subtype(entitlement) = golden_pickaxe_entitlement
    Price : int = 500     # V-Bucks。50〜5000の範囲で、50刻みで指定する
🎪
まとめ売り(bundle_offer)もできる

複数の商品をまとめてお得に売りたいときはentitlement_offerの代わりにbundle_offerを使います。福袋のように、複数のオファーをひとつの商品としてまとめられます(入れ子は最大5階層まで)。

📝 演習問題 02

演習01で作ったspeed_boost_entitlement用の値札を、Name := "スピードブースト"、 Price := 150(V-Bucks)として作ってみましょう。

verse
speed_boost_offer<public> := class(entitlement_offer):
    Name : string = "スピードブースト"
    ShortDescription : string = "しばらくの間、足が速くなる"
    Description : string = "使用すると数秒間だけ移動速度がアップします。"
    EntitlementType : subtype(entitlement) = speed_boost_entitlement
    Price : int = 150
04ふつう

お店を開く(購入ダイアログ)

商品と値札ができたら、あとはプレイヤーに「陳列棚」を見せるだけです。ボタンと組み合わせてみましょう。

verse — shop_device.verse
using { /Fortnite.com/Devices }
using { /Verse.org/Simulation }

shop_device := class(creative_device):
    @editable
    ShopButton : button_device = button_device{}

    OnBegin<override>()<suspends> : void =
        ShopButton.InteractedWithEvent.Subscribe(OnShopButtonPressed)

    OnShopButtonPressed(Agent : agent) : void =
        ShowOffersDialog(Agent, array{golden_pickaxe_offer{}})   # 模擬店の陳列棚を開く

ShowOffersDialogの第2引数は配列なので、複数の商品を同時に並べることもできます。

📝 演習問題 03

ShowOffersDialogの配列にspeed_boost_offer{}も追加して、 黄金のツルハシとスピードブーストの2商品が同時に並ぶお店にしてみましょう。

verse
OnShopButtonPressed(Agent : agent) : void =
    ShowOffersDialog(Agent, array{golden_pickaxe_offer{}, speed_boost_offer{}})
05応用

応用: 支払いを確実に確認する

お店を開いただけでは、まだ完成ではありません。「本当に支払いが完了したか」を確実に確認してから、 次の処理(ごほうびを渡すなど)を行う必要があります。

たとえ話でわかる 誠実なレジ係

模擬店の店員さんを思い浮かべてください。「お客さんが払ったって言ってたから、たぶん大丈夫だろう」と商品を渡すのは危険です。 誠実な店員さんは、レジの記録(領収書)を見て、本当に支払いが記録されたことを確認してから商品を渡しますよね。

Verseでも同じで、BuyOfferを呼んだ「その場の結果」だけを信用するのではなく、 GetEntitlementChangedEventという「レジの記録係」からの通知を確認するのが正しい作法です。

verse
shop_device := class(creative_device):
    @editable
    ShopButton : button_device = button_device{}

    OnBegin<override>()<suspends> : void =
        ShopButton.InteractedWithEvent.Subscribe(OnShopButtonPressed)
        # レジの記録係(購入完了通知)を、最初にひとつだけ登録しておく
        GetEntitlementChangedEvent().Subscribe(OnEntitlementChanged)

    OnShopButtonPressed(Agent : agent) : void =
        ShowOffersDialog(Agent, array{golden_pickaxe_offer{}})

    # 「本当に買えたとき」だけ、ここが呼ばれる
    OnEntitlementChanged(Agent : agent, Entitlement : subtype(entitlement)) : void =
        if (Entitlement = golden_pickaxe_entitlement):
            Print("購入ありがとうございます!")
🔍
所持確認にはGetPurchasedEntitlementsを使う

「このプレイヤーはすでにこの商品を持っているか?」を確認したいときはGetPurchasedEntitlements(Agent)を使います。すでに持っている耐久アイテムを二重に売ってしまう事故を防げます。

📝 演習問題 04

OnEntitlementChangedの中で、golden_pickaxe_entitlementだけでなく speed_boost_entitlementが買われたときにも「スピードブーストを購入いただきありがとうございます!」と表示するように、 条件分岐を追加してみましょう。

verse
OnEntitlementChanged(Agent : agent, Entitlement : subtype(entitlement)) : void =
    if (Entitlement = golden_pickaxe_entitlement):
        Print("購入ありがとうございます!")
    else:
        if (Entitlement = speed_boost_entitlement):
            Print("スピードブーストを購入いただきありがとうございます!")
06応用

応用: ごほうびと組み合わせる

支払いが確認できたら、初級・中級編で学んだitem_granter_deviceと組み合わせて、実際にごほうびを渡してみましょう。

verse — reward_shop_device.verse
reward_shop_device := class(creative_device):
    @editable
    ShopButton : button_device = button_device{}
    @editable
    BonusGranter : item_granter_device = item_granter_device{}

    OnBegin<override>()<suspends> : void =
        ShopButton.InteractedWithEvent.Subscribe(OnShopButtonPressed)
        GetEntitlementChangedEvent().Subscribe(OnEntitlementChanged)

    OnShopButtonPressed(Agent : agent) : void =
        ShowOffersDialog(Agent, array{golden_pickaxe_offer{}})

    OnEntitlementChanged(Agent : agent, Entitlement : subtype(entitlement)) : void =
        if (Entitlement = golden_pickaxe_entitlement):
            BonusGranter.GrantItem(Agent)   # 領収書を確認してから、初めてごほうびを渡す
            Print("購入ありがとうございます! ボーナスアイテムを渡しました")
🧩
初級編・中級編の知識がそのまま活きる

item_granter_deviceとbutton_deviceの使い方は初級編・第11章と中級編・第17章で学んだものと完全に同じです。島内取引は「決済の確認」という新しいピースが1つ増えるだけで、あとは今まで通りの部品の組み合わせでできています。

📝 総合チャレンジ問題

「vip_pass_entitlement」(耐久型)という商品を定義し、値札「vip_pass_offer」(Name := "VIPパス", Price := 1000)を作成。 さらにボタンでお店を開き、購入されたらitem_granter_deviceでVIP専用アイテムを渡す一連の流れを、 この章までの知識を組み合わせて実装してみましょう。

ヒント: 02〜06章のコードを、名前だけ変えてそのままつなげれば完成します。
verse — vip_shop_device.verse
vip_pass_entitlement := class(entitlement):
    Consumable : logic = false

vip_pass_offer<public> := class(entitlement_offer):
    Name : string = "VIPパス"
    ShortDescription : string = "特別エリアに入れる証"
    Description : string = "購入すると、VIP専用エリアに入場できるようになります。"
    EntitlementType : subtype(entitlement) = vip_pass_entitlement
    Price : int = 1000

vip_shop_device := class(creative_device):
    @editable
    ShopButton : button_device = button_device{}
    @editable
    VipItemGranter : item_granter_device = item_granter_device{}

    OnBegin<override>()<suspends> : void =
        ShopButton.InteractedWithEvent.Subscribe(OnShopButtonPressed)
        GetEntitlementChangedEvent().Subscribe(OnEntitlementChanged)

    OnShopButtonPressed(Agent : agent) : void =
        ShowOffersDialog(Agent, array{vip_pass_offer{}})

    OnEntitlementChanged(Agent : agent, Entitlement : subtype(entitlement)) : void =
        if (Entitlement = vip_pass_entitlement):
            VipItemGranter.GrantItem(Agent)
            Print("VIPパス購入ありがとうございます!")
